# 其乐 / 百度贴吧主楼截图（AstrBot 插件）

自动检测群消息中的其乐 Keylol 或百度贴吧帖子链接，并返回适合手机阅读的 PNG 图片。两站默认都优先使用本地受控浏览器直接截取真实移动网页，环境不可用时自动回退到安全清洗后的 HTML；贴吧同时支持 OneBot/NapCat 上报的 QQ JSON 分享卡片。

### 通过 AstrBot WebUI 安装或更新

在 AstrBot WebUI 的插件管理中使用“＋”或安装入口，粘贴上面的 GitHub 仓库链接即可安装；之后在同一插件的更新入口检查并拉取新版本。公开仓库不需要在运行 AstrBot 的电脑上登录 GitHub。AstrBot 官方文档说明了通过 URL 或文件安装插件的方式：<https://docs.astrbot.app/use/webui.html>

AstrBot 本体用 `uv` 安装，与插件安装和更新是两件不同的事：升级 AstrBot 本体不会自动升级本插件，插件更新也不会替换 AstrBot 本体。网页截图所需的 Playwright 浏览器依赖必须安装在运行该 AstrBot 实例的对应 Python 环境中；不要只在系统 Python 或另一套虚拟环境中安装。浏览器依赖的安装说明见下方“其乐 iPhone 网页截图与目录分图”章节。

从 0.5.0 或旧 ZIP 手动安装的实例可能没有 `repo` 更新来源。首次切换到链接更新前，请先备份 AstrBot 配置；然后在已安装插件目录的 `metadata.yaml` 中补入下面这一行，再保存并重载插件：

```yaml
repo: https://github.com/ureiCyber/astrbot_plugin_keylol_tieba_screenshot
```

重载只会重新加载当前磁盘上的插件代码，不会下载更新；补入 `repo` 后再使用 WebUI 的更新入口。不要直接上传同名 ZIP 覆盖现有插件目录，也不要默认卸载插件来“更新”，以免造成不必要的配置迁移或丢失。若更新失败，保留配置备份并检查网络、仓库地址和 AstrBot 日志。

### 公开分发与隐私安全

- 每位用户都应只在自己信任的 AstrBot 本地 WebUI 中填写 `keylol_cookie` 和 `tieba_cookie`；不要把 Cookie、`BDUSS`、`STOKEN` 或配置文件发到 GitHub Issue、聊天、群组或公开日志中。
- Cookie 是登录凭证。请优先使用权限受限的专用账号，怀疑泄露时立即退出对应账号会话或修改密码，使旧凭证失效。
- Cookie 可访问的受限帖子或附件，可能会被插件截图并转发到你配置的群。请谨慎设置群范围、账号权限和可访问内容；公开仓库本身不会收集或替你托管这些 Cookie。

## 使用

把本目录放进 AstrBot 的 `data/plugins/astrbot_plugin_keylol_screenshot/`，然后在 WebUI 中重载插件。

在群里直接发送或转发包含下列格式链接的普通消息即可自动触发：

```text
https://keylol.com/t1046223-1-1
https://tieba.baidu.com/p/10937213244?share_from=qq
```

插件会自动读取完整主楼并在原群返回图片，不需要添加指令前缀。贴吧 QQ 分享卡片会从 `meta.news.jumpUrl` 中提取真实帖子链接；其他 JSON 卡片格式会递归查找有效的贴吧帖子 URL。

同一群内相同链接默认 60 秒内只处理一次；单条消息默认只处理第一个链接，这些行为可在插件配置中调整。

截图默认以 390×844 CSS 像素的 iPhone Safari 视口访问两站真实移动网页，直接保留网页的移动页面布局和字号；`content_width` 可在 320-440 之间调整，并同时作用于其乐和贴吧。网页截图末尾才会追加来源、作者等截图信息，不会覆盖原页面内容。

### 0.5.0 百度贴吧受控浏览器截图

贴吧新增 `tieba_render_engine`，默认值为 `auto`：优先用受控浏览器打开 `tieba.baidu.com` 的真实网页并截取主楼；浏览器不可用，或遇到验证码、反爬限制、页面 DOM 不兼容等情况时，自动回退到安全清洗后的 HTML。`playwright` 强制网页截图并在失败时返回错误，`html` 始终使用安全 HTML 兼容流程。贴吧不适用其乐的目录分图配置，仍按一个主楼返回一张图。

`browser_capture_timeout_ms`、`content_width` 和 `proxy_url` 对其乐与贴吧的网页截图都生效；前者控制打开、懒加载预热和截图的最长等待时间，后两者分别控制移动网页宽度和浏览器网络代理。

### 0.4.9 目录多图发送修复

修复自动识别链接时目录帖子只发出第一张图的问题。原因是自动处理会调用 `stop_event()` 阻止同一消息继续进入其他处理器，而 AstrBot 在第一轮响应后也会停止消费这个处理器后续逐张 `yield` 的结果。现在同一帖子生成的所有目录截图会作为一个标准消息链一次提交；每个目录仍对应一个独立 PNG 图片组件，并保持目录顺序，不会重新拼成一张长图。

同时修复未配置 `keylol_cookie` 时，只要公开页面中出现登录后附件提示便直接回退 HTML 兼容模式的问题。现在仍会继续尝试 iPhone 网页截图和目录拆分；受限附件保持网页当前的登录提示。若需要显示登录后附件，仍应在 AstrBot WebUI 中配置有效的 `keylol_cookie`。日志会记录截图引擎、目录拆分设置、是否配置 Cookie，以及实际生成和加入消息链的图片数量，便于确认运行版本与分图结果。

### 0.4.8 其乐 iPhone 网页截图与目录分图

`keylol_render_engine` 默认值为 `auto`：插件使用独立的 Playwright 浏览器，以 iPhone Safari 的设备参数访问其乐移动页面，然后直接截取页面布局。截图保留网页正文的自然排版，不再把图片下载后重新拼进 HTML；标题、作者、发布时间和来源等额外信息会作为普通内容追加在图片末尾，不会悬浮遮挡正文。长页会始终保持 390×844 的真实手机视口逐屏下滑截图并无缝拼接，既能触发懒加载，也避免浏览器为了全页截图临时拉高视口而改变网页布局。

帖子带有目录时，`split_toc_sections` 默认开启：目录中的每个项目会单独生成一张图，并按网页中的目录顺序发送，避免把多个章节的图片挤在同一张长图里。`max_toc_sections` 默认 12，范围 1-20；关闭 `split_toc_sections` 后则整帖只生成一张图。没有目录的帖子仍只生成一张图。

网页模式不再由插件逐张下载并转成 Base64。它会直接读取 Discuz 页面已有的 `file`、`zoomfile`、`data-src`、`srcset` 等懒加载地址，按正文顺序逐张交给浏览器加载并限速重试，必要时再回退同一附件的其乐主站地址。这样既能触发长帖懒加载，也能避免大量附件同时请求而被 CDN 限流。最终仍失败的图片会变成醒目的失败提示，不会静默留下空白。

可选值：

- `auto`：优先 iPhone 移动网页截图；Playwright、浏览器、页面或尺寸不满足要求时自动使用原有兼容模式（兼容模式只生成一张图）。
- `playwright`：强制网页截图，便于排查环境问题；失败时直接返回可读错误。
- `html`：始终使用 0.4.6 的安全清洗、图片下载与 AstrBot HTML 渲染流程。

网页模式需要运行 AstrBot 的同一台机器上存在 Chrome、Edge，或 Playwright Chromium。插件依赖安装会安装 Playwright Python 组件，但不会自动下载数百 MB 的浏览器内核；若服务器没有 Chrome/Edge，可在 AstrBot 的 Python 环境中执行：

```text
python -m playwright install chromium
```

每次截图都使用全新的临时浏览器环境。`keylol_cookie` 只作为 `keylol.com` 与 `www.keylol.com` 的主机 Cookie 注入，不会发送给 `blob.keylol.com` 或第三方域名；贴吧浏览器模式只把 `BDUSS` 和可选的 `STOKEN` 注入 `tieba.baidu.com` 与 `www.tieba.baidu.com`，绝不向图床或第三方域名发送。外站导航、脚本、WebSocket、下载和非 GET 请求都会被阻止，仅放行当前帖子的页面、站内样式、附件图片和所需的同帖请求。截图结束后浏览器环境立即销毁。

`browser_capture_timeout_ms` 控制单个网页分段打开、懒加载预热和截图的基础等待上限，默认 120000 毫秒；启用其乐目录分图时，每个额外目录项目会额外预留 30 秒，整体上限为 600 秒。过长、图片过多、验证码/反爬限制、DOM 不兼容或浏览器无法安全处理的帖子会在对应的 `auto` 模式下回退安全 HTML。右侧 Codex 浏览器、个人 Chrome 与 AstrBot 浏览器互不共享登录状态，仍需在 AstrBot WebUI 中配置对应 Cookie。

`adaptive_height` 只影响 HTML 兼容模式，用于裁掉短帖底部由默认视口产生的多余纯白区域；iPhone 网页截图模式始终使用移动页面的完整高度。

两站浏览器请求使用 iPhone Safari UA 和移动视图参数，截图尺寸默认是 390×844 CSS 像素；页面中的懒加载资源会在截图前通过有限滚动触发并等待完成。贴吧回退到 API/HTML 兼容流程时，客户端接口仍保留其协议要求的 Android 客户端 UA，图片下载使用受控的请求头。

也可以使用手动指令：

```text
/keylol https://keylol.com/t1046223-1-1
/tieba https://tieba.baidu.com/p/10937213244
```

不传链接时使用插件配置中的 `default_url`：

```text
/keylol
```

验证 Cookie 是否有效（必须使用 AstrBot 管理员账号私聊发送；群管理员身份不会自动获得 AstrBot 管理员权限）：

```text
/keylol_check
/tieba_check
```

### 0.4.6 媒体附件修复（兼容模式）

本版本修复了登录后才能查看的其乐附件图片在截图中空白或不可见的问题。对需要认证的图片，插件会优先请求其乐主站附件接口；仅在安全校验通过时才回退到受信任的 CDN 地址。若内嵌下载临时失败，插件会保留经过校验的 CDN 原图地址，让截图渲染器再尝试加载一次，避免静默丢失附件。

视频、音频和嵌入式播放器无法在静态 PNG 中播放：有可用封面时，截图会显示媒体海报；没有封面时，会显示清晰的“打开原帖查看媒体”卡片，提示从原帖打开原始内容。

公开帖子无需填写 `keylol_cookie` 即可截图；帖子中被其乐标记为“登录后才能查看”的附件或资源仍然需要有效 Cookie。未配置 Cookie 时，插件会返回已经公开的主楼内容，并在图片中标明仍有受限资源。Cookie 会以明文写入 AstrBot 的配置目录，请只在可信的私有部署中使用，且不要把 Cookie 发送到聊天中。

在 Chrome 或 Edge 中获取：

1. 正常登录 `https://keylol.com/`。
2. 按 `F12` 打开开发者工具，进入 **Network（网络）**。
3. 确认页面右上角显示自己的账号而不是“登录”，然后刷新目标帖子。
4. 在 Network 中右键类型为 `document`、名称类似 `t1046223-1-1` 的帖子请求。
5. 选择 **Copy（复制）→ Copy as cURL (bash)**，粘贴到本地记事本。
6. 找到 `-b '...'`，或 `-H 'cookie: ...'`。只复制引号内的完整 Cookie 值，粘贴到 AstrBot WebUI 的本插件配置 `keylol_cookie` 中并保存。
7. 如果复制出的 cURL 中仍没有 `-b` 或 `cookie:`，说明这次请求没有携带登录 Cookie；重新登录其乐后再刷新一次。
8. 使用 AstrBot 管理员账号私聊发送 `/keylol_check`。验证成功后再使用 `/keylol`。群管理员身份不会自动获得此权限。

Cookie 相当于登录凭证。不要把它发给其他人，也不要提交到 GitHub。

## 百度贴吧 Cookie（必填）

贴吧支持的配置项为 `tieba_cookie`。请粘贴浏览器发送给 `tieba.baidu.com` 的完整 Cookie；其中必须包含 `BDUSS`，建议同时包含 `STOKEN`。API 兼容流程只提取 `BDUSS` 并提交给百度贴吧官方域名 `c.tieba.baidu.com` 以读取帖子及验证登录状态；浏览器模式只把 `BDUSS` 和可选的 `STOKEN` 注入 `tieba.baidu.com` 与 `www.tieba.baidu.com`。Cookie 绝不向图床或任何第三方域名发送；完整配置值仍会以明文保存在 AstrBot 配置目录中。

在 Chrome 或 Edge 中获取：

1. 使用准备给 Bot 的百度账号登录 `https://tieba.baidu.com/`，推荐使用专用小号。
2. 打开任意可以正常浏览的贴吧帖子，按 `F12` 打开开发者工具。
3. 进入 **Network（网络）**，刷新当前帖子。
4. 在请求列表中选中类型为 `document`、地址形如 `https://tieba.baidu.com/p/数字` 的请求。
5. 在右侧 **Headers（标头）→ Request Headers（请求标头）** 中找到 `Cookie`，复制冒号后面的完整值。
6. 如果标头面板没有直接显示 Cookie，可右键该请求，选择 **Copy → Copy as cURL (bash)**，粘贴到本地记事本，然后复制 `-b '...'` 或 `-H 'cookie: ...'` 引号内的内容。
7. 确认复制内容中至少存在 `BDUSS=...`。如同时存在 `STOKEN=...`，一并保留。
8. 把完整 Cookie 粘贴到 AstrBot WebUI 的本插件配置 `tieba_cookie`，保存并重载插件。
9. 使用 AstrBot 管理员账号私聊发送 `/tieba_check`；显示当前贴吧账号后，再在群里发送链接或 QQ 分享卡片测试。群管理员身份不会自动获得此权限。

`BDUSS` 是高权限且可能长期有效的登录凭证。不要把 Cookie 发到群聊、Issue、日志或代码仓库；不要使用主账号；怀疑泄露时应立即退出该百度账号的登录会话或修改密码，使旧凭证失效。

贴吧浏览器模式只读取真实网页并生成主楼截图，不会执行发帖、回复、点赞、签到或其他写操作；自动回退时才使用百度贴吧只读客户端接口，且只请求帖子第一页。验证码、反爬限制、DOM 不兼容、已删除、审核中、被屏蔽或当前账号无权查看的内容仍可能无法截图。

在 `html` 兼容模式或 `auto` 回退流程中，正文中的其乐站内图片默认会由插件在截图前下载并内嵌，下载请求会携带帖子 Referer、图片 Accept 和可选代理。需要认证的附件图片优先使用其乐主站附件接口，并在通过安全校验后回退到受信任 CDN；若仍未能内嵌，截图渲染器会再尝试加载经过校验的站内原图地址。登录 Cookie 只发送给精确的 `keylol.com` 或 `www.keylol.com` 主机，不会发送给任意其他子域、重定向后的外站或第三方域名。第三方域名图片会在清洗阶段移除，避免渲染器访问任意外部或内网地址。附件服务器返回通用二进制类型时，插件会按 PNG/JPEG/GIF/WebP/AVIF 文件特征识别。仍未能下载的站内图片会在截图中显示数量提示，不再静默生成空附件区。

Discuz 附件图片会优先读取 `zoomfile`、`file`、`data-src` 等真实图片地址，而不是空白懒加载占位图；图片会直接显示在截图里，不需要用户另行点击下载附件。

附件区域只保留实际图片；文件类型图标、文件名、大小、下载次数和“下载附件”操作链接会从截图中移除。视频、音频和嵌入式播放器会以封面或“打开原帖查看媒体”卡片表示，因为 PNG 截图本身无法播放这些媒体。

正文图片按自然尺寸显示；只有图片超过正文宽度时才会等比例缩小。

## 当前截图范围

- 帖子标题
- 主楼作者与发布时间
- 主楼正文中的文字、链接、列表、表格和图片
- 1 楼内登录后可见的附件与资源
- 来源链接

解析器会明确寻找“1 楼”标记；遇到后续楼层不会继续处理。不会包含导航栏、用户侧栏、广告、2 楼及后续回复、快速回复框和页脚。

贴吧网页截图会从页面的楼层元数据或明确的“1楼”尾栏中选择主楼，并隐藏后续楼层、楼中楼、广告和推荐内容；音视频会替换为静态提示。进入 HTML 兼容模式后，则从客户端接口第一页结果中严格选择 `floor == 1` 的主楼，并保留文本、图片和链接的原始顺序。

本插件为个人维护版本，暂不用于插件市场发布。
